# 沪皖红联成果展示网站技术需求

版本：V0.3  
日期：2026年10月11日  
对象：前端、后端、产品及验收人员  
配套原型：`dist/index.html`（本地预览，未部署）

## 1. 产品定位与确定条件

网站以红二十五军长征路线为主线，将各组学生在不同教学节点完成的内容组织为共同成果，供学生及家长在课后查看。老师统一整理、上传、发布，用户浏览已发布内容。

确定条件：

- 参加学生共81人。分多少组、每组人数和具体教学节点均待确定，不写死4至6组或每组3至5人。
- 一个小组对应一个教学节点，一个教学节点最多关联一个小组。历史路线上的普通节点不必安排小组。
- 采用“节点”组织内容，不预设每个节点都是困难，不限定作品是解决方案。
- 节点游戏形式待定。首版使用通用文字、图片、视频承载内容，不实现具体游戏引擎。
- 网站角色只有管理员（老师）和用户（学生、家长等）。学生不注册独立账号，不自主提交。
- 点击节点后可查看文字、图片及视频。作品内容与历史背景分别标识。
- 课程为180分钟，制作是最长环节，暂定110分钟；每组一名助教，开场为多媒体电脑路线演示；不设置独立互测环节。

本次先交付本地原型，不部署。原型的教师入口是角色流程演示，不是真实登录；本地上传保存在当前浏览器。正式版本须接入管理员身份校验、服务端存储和跨设备访问。

## 2. 首版范围与边界

| 能力 | 本地原型 | 正式开发要求 |
| --- | --- | --- |
| 红二十五军路线与主要节点 | 已内置主要节点，附来源 | 教学团队核准后作为路线配置发布 |
| 用户浏览 | 路线、详情、作品集合、课程说明 | 同一观看链接可供学生及家长持续访问 |
| 老师录入 | 关联小组、文字、图片、视频 | 登录后操作；服务端验证权限 |
| 草稿与发布 | 两份独立内容，支持更新与撤回 | 数据库持久保存，发布原子操作 |
| 新增节点 | 在指定节点后插入课堂节点 | 地点、历史背景和关联顺序须核准 |
| 媒体保存 | 浏览器IndexedDB | 文件或对象存储，图片预览、视频播放 |
| 分享 | 导出携带已发布媒体的只读HTML | 观看链接；无需手工复制到每台设备 |
| 用户账号 | 无 | 用户默认只读访问，不强制注册个人账号 |

本次不实现自动运行节点游戏、学生提交、助教独立角色、课堂打分、实时协同、站外内容自动抓取或部署。视频播放属于核心范围，不能列为未来扩展。

## 3. 路线与教学节点

### 3.1 路线基线

路线采用红二十五军资料，不能直接把上传整理稿中的混合路线当作已核准路线。正式长征段从何家冲出发，以永坪到达和会师为终点。长征前的皖西活动如需展示，应作为独立“历史前序”，不混入正式长征日期序列。

原型选取以下13个主要历史节点。这是展示路线的初始内容，不等于最终教学节点数，不代表13个小组，也不代表全部行军途经地点。

### 3.2 教学节点规则

1. 历史节点始终可以查看，不因没有小组作品而消失。
2. 老师可将历史节点标记为教学节点，并关联一个小组；未关联时显示“小组待确定”。
3. 同一活动中小组名称或编号唯一，小组与教学节点的关联一对一，由服务端约束。
4. 新增教学节点应插入核准的路线位置，并提供地点、背景及来源，不由系统编造历史事件。
5. 统计区分“历史节点数”“教学节点数”“已关联小组数”“已发布内容数”。分组未定时显示“待确定”，不能用13个历史节点推算为13组。
6. 节点ID长期稳定，排序变化不改变作品归属。

## 4. 角色与权限

| 角色 | 权限 | 正式身份方式 |
| --- | --- | --- |
| 管理员（老师） | 配置课程和节点，关联小组，上传素材，保存草稿，发布、更新、撤回内容 | 管理员登录，服务端会话及活动权限校验 |
| 用户 | 查看当前活动的已发布路线、文字、图片、视频和作品集合 | 持有该活动观看链接，只读访问 |

助教帮助孩子完成内容和收集素材，网站不单独设置助教角色。用户不能上传、编辑或发布。权限必须在服务端执行；隐藏按钮或客户端角色切换不能构成正式访问控制。

管理会话采用安全Cookie或等效安全方案，不把密码、会话密钥放入客户端代码。观看接口与观看素材不得暴露草稿、管理凭据或其他活动内容。观看令牌须不可枚举；持有链接即具备该活动的只读权限。

## 5. 页面与交互

建议正式路由：

| 页面 | 路径 | 内容 |
| --- | --- | --- |
| 路线首页 | `/show/:viewerToken` | 课程介绍、81人参与、分组状态、路线示意、节点入口 |
| 节点详情 | `/show/:viewerToken/nodes/:nodeId` | 历史文字、小组文字、图片与视频 |
| 小组作品集合 | `/show/:viewerToken/works` | 已发布内容按路线顺序排列 |
| 课程说明 | `/show/:viewerToken/about` | 活动说明、上传方式、资料来源 |
| 管理登录 | `/admin/login` | 管理员身份验证 |
| 老师工作台 | `/admin/activities/:activityId` | 节点列表、内容编辑、状态、发布入口 |
| 课程配置 | `/admin/activities/:activityId/settings` | 标题、介绍、人数、观看链接 |

### 5.1 路线页

- 主要区域展示红二十五军路线，节点编号和名称可读，提供同顺序的节点列表。
- 点击节点更新选中状态，并可打开详情。普通历史节点和教学节点使用不同标记。
- 未定分组显示“待确定”；作品数量以已发布数据统计。
- 路线示意注明非精确道路、不包含全部途经地点。
- 桌面适合投屏，手机可横向滑动地图，并通过节点列表访问全部节点。页面整体不得横向溢出。

### 5.2 节点详情

详情按以下顺序展示，支持上一节点、下一节点及关闭或返回：

1. 名称、地点、时间与历史背景，附资料来源。
2. 小组名称、内容标题、通用文字，活动形式选填。
3. 图片列表，点击查看完整图片，不强制裁切作品。
4. 视频播放器，支持暂停、进度拖动、音量和全屏；手机使用内联播放。

未上传媒体显示明确空状态；不得使用虚构儿童作品填充。未发布内容不进入用户接口，用户只看到“内容待上传或发布”。小组内容标识为课堂内容，不能混写为历史事实。

### 5.3 老师工作台

- 节点列表显示名称、顺序、小组关联和是否已发布。
- 内容表单提供教学节点开关、小组名称、内容标题、文字、选填活动形式，以及图片和视频上传。
- 保存草稿、发布、更新发布和撤回发布采用独立动作与明确反馈。
- 草稿保存失败时保留当前输入，不能提示成功。
- 离开未保存表单须提醒；不能默默丢失文字或刚选择的文件。
- 已发布节点改变小组关联时须同时更新发布，或先撤回，不能让用户看到不一致的小组归属。

## 6. 数据结构

建议数据库实体如下。接口JSON采用camelCase，数据库内部命名方式由开发团队统一。

| 实体 | 关键字段 | 约束 |
| --- | --- | --- |
| Activity | id, title, intro, participantCount, timezone, viewerToken, ownerId, configVersion | 初始人数81；时区Asia/Shanghai |
| RouteNode | id, activityId, name, location, dateLabel, order, position, historyText, sourceRefs, isTeaching | 同活动排序唯一；稳定ID |
| Group | id, activityId, name, nodeId | 同活动组名唯一、nodeId唯一；只关联教学节点 |
| NodeRecord | id, nodeId, draftVersion, draftPayload, publishedVersion, publishedPayload, publishedAt | 一个节点一份当前内容记录；草稿与发布快照独立 |
| Asset | id, activityId, nodeId, kind, mime, size, storageKey, originalName, caption, status | 只能被同活动内容引用；素材不可凭ID越权访问 |
| PublicationLog | id, activityId, nodeId, actorId, action, version, timestamp | 记录发布、更新与撤回操作 |

通用内容结构：

```ts
type NodeContent = {
  title: string;             // 发布时必填，1—80字
  text: string;              // 0—3000字，不限定为解决方案
  activityFormat?: string;   // 选填，0—80字，具体游戏方式待定
  imageIds: string[];
  videoIds: string[];
};
```

发布规则：内容标题必填；文字、图片、视频至少提供一项；关联有效小组与教学节点。历史文字由RouteNode管理，不要求把历史背景重复填入作品文本。不设置测试发现、修改理由或解决方案等必填字段。

字段长度按Unicode字符计数。历史背景、课堂活动说明和小组内容分开保存。富文本若后续启用，须服务端清洗；首版使用纯文本及安全转义。

## 7. 媒体上传与播放

初始产品上限与原型一致，正式实现可以配置：

| 类型 | 格式 | 单个上限 | 单节点上限 | 展示要求 |
| --- | --- | --- | --- | --- |
| 图片 | JPEG、PNG、WebP | 10MB | 6张 | 保存原图与缩略图，点击查看完整图片 |
| 视频 | MP4、WebM | 50MB | 2段 | 原生播放器；建议MP4使用浏览器普遍支持的编码 |

上传流程：选择文件 → 客户端初检 → 服务端检查类型及大小 → 存储成功 → 返回assetId → 加入草稿 → 发布后用户可见。

- 文件类型依据实际文件内容验证，不能只相信扩展名或客户端MIME。
- 上传失败可重试，不生成有效素材记录；草稿不能引用未完成的上传。
- 视频展示需提供正确Content-Type，并支持Range请求和206响应，避免每次播放下载完整文件。
- 已发布素材的访问规则与活动观看权限一致；草稿素材不得通过观看接口取得。
- 正在被发布版本引用的素材不能删除；移除草稿中的素材不应破坏旧发布版本。
- 图片与视频使用延迟加载，不将所有视频自动播放或预加载进首页。

## 8. 草稿、发布与配置版本

| 操作 | 草稿 | 当前发布快照 | 用户结果 |
| --- | --- | --- | --- |
| 保存草稿 | 新版本 | 保留 | 仍看到旧发布内容 |
| 首次发布 | 保留 | 创建快照 | 开始展示 |
| 修改并保存 | 新版本 | 保留 | 不出现半成品 |
| 更新发布 | 保留 | 原子替换 | 展示新版本 |
| 撤回发布 | 保留 | 取消当前快照 | 小组内容暂时不展示，历史节点仍可查看 |

正式版的路线配置也需要草稿与已发布版本。调整节点顺序、史料或组关联后，只有发布配置才改变观看端。发布配置时验证所有现有内容归属，删除或取消教学节点时先处理其已发布作品。

管理写操作携带expectedVersion。并发冲突返回409并保留用户当前输入。重复提交发布或上传应通过Idempotency-Key去重，发布状态、版本与关联操作必须在事务或等效原子机制中执行。

## 9. 正式接口基线

本地HTML不调用下列接口；此表供后续服务端实现。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/api/admin/session` | 验证管理员，建立会话 |
| DELETE | `/api/admin/session` | 退出会话 |
| GET / PATCH | `/api/admin/activities/:id` | 读取、保存课程配置草稿 |
| GET / PUT | `/api/admin/activities/:id/route` | 读取、保存节点、排序和小组关联 |
| POST | `/api/admin/activities/:id/route/publish` | 发布核准的路线配置 |
| POST | `/api/admin/activities/:id/assets` | 上传文件，返回assetId及处理状态 |
| DELETE | `/api/admin/assets/:assetId` | 删除未被发布版本引用的素材 |
| GET / PATCH | `/api/admin/nodes/:nodeId/content` | 读取、保存内容草稿 |
| POST | `/api/admin/nodes/:nodeId/publish` | 发布或更新当前草稿 |
| POST | `/api/admin/nodes/:nodeId/withdraw` | 撤回发布 |
| GET | `/api/view/:viewerToken` | 返回已发布课程、路线、小组统计 |
| GET | `/api/view/:viewerToken/nodes/:nodeId` | 返回节点背景和已发布图文、视频 |
| GET | `/api/view/:viewerToken/works` | 返回已发布小组内容集合 |

保存内容请求示例：

```json
{
  "expectedVersion": 2,
  "content": {
    "title": "我们记录的节点故事",
    "text": "这里填写孩子们完成的通用节点内容。",
    "activityFormat": "",
    "imageIds": ["asset_image_01"],
    "videoIds": ["asset_video_01"]
  }
}
```

错误响应格式统一：

```json
{
  "code": "GROUP_ALREADY_ASSIGNED",
  "message": "这个小组已经关联其他节点。",
  "field": "groupId"
}
```

400为字段或业务校验失败，401为未登录，403为无管理权限，404为不可访问的活动或节点，409为版本或关联冲突，413为文件过大，415为不支持的媒体类型。5xx不返回内部凭据或堆栈。所有接口和素材下载均校验活动归属，不通过不透明ID假定安全。

## 10. 验收清单

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 初始课程 | 显示81名学生，分组待定；13个主要历史节点不自动生成13个小组 |
| A02 | 历史路线 | 何家冲至永坪顺序正确，来源可查看，不混入其他部队路线 |
| A03 | 节点打开 | 可查看文字、图片、视频三个内容区域及空状态 |
| A04 | 小组关联 | 每组一个教学节点；重复关联被拒绝，普通历史节点可无小组 |
| A05 | 通用内容 | 可发布故事、记录、模型说明等，不要求填写解决方案或测试报告 |
| A06 | 上传 | 支持有效图片和视频；格式、大小、数量错误有明确提示 |
| A07 | 草稿保护 | 保存草稿不改变已发布内容；离开未保存表单有提醒 |
| A08 | 更新与撤回 | 发布原子更新，撤回后用户只看到历史背景及等待状态 |
| A09 | 刷新保存 | 原型同浏览器刷新仍有内容；正式版跨设备可读取相同发布版本 |
| A10 | 用户权限 | 用户不能上传或修改，观看数据中无草稿；正式管理接口必须登录 |
| A11 | 视频播放 | 手机、电脑可播放与暂停、拖动进度；正式服务支持Range |
| A12 | 小组变更 | 已发布内容与小组归属不能出现不一致状态 |
| A13 | 分享 | 原型导出只读HTML只含已发布内容及对应媒体，不含草稿与上传入口 |
| A14 | 响应式 | 1366×768、1920×1080及390宽度可操作，页面无整体横向溢出 |
| A15 | 后续访问 | 正式网站在课程结束后仍可按观看链接访问；记录和素材不会随服务重启丢失 |
